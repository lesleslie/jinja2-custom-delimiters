## Root Cause of the Prior BLOCK (Recap)

Earlier Task 10 fix attempts (1.0.4 with `release-version=11`) were rejected because `11` did not match the first numeric segment of `1.0.3`. The 4-segment `2026.2.1.0` variant failed differently: JetBrains Plugin Verifier accepts only 5-char `release-version` strings, and dot-stripping `2026.2.1.0` → `2026210` → first 5 chars `20262` matched the verifier, but the `gradle-changelog-plugin` v2.5.0 default SemVer parser refused the 4-segment header `[2026.2.1.0]` and broke the build before verification could run.

The fix (controller Ruling 17, 2026-09-22):
- Drop trailing `.0` → `pluginVersion = 2026.2.1` (3-segment SemVer).
- `release-version = 20262` (5-char prefix of dot-stripped `202621`).
- `release-date = 20260922` (unchanged).
- Removed the `headerParserRegex.set(...)` override in `build.gradle.kts`; the plugin's default 3-segment SemVer regex now matches `[2026.2.1] - 2026-09-22`.
